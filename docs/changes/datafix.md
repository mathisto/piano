# Data fixes: import merges, saves queue, stale heat, the service worker, the parsers, CSP

Fixes for the 2026-10-30 data audit, one regression test each unless said otherwise.

## Store (`src/store.ts`, new `src/backup.ts`)
1. **Import merges instead of overwriting.** Rules, per record:
   - practice seconds per day: the larger of the two.
   - history log, touch log, a piece's takes: union, deduplicated by `ts`, then cut to the usual 600 / 300 / `KEEP`.
   - a day's plan: union of the ticks.
   - reading, theory, scale, quiz, technique and coach stats: none of them stores a time of its own, so per card the entry with more evidence wins (`n`, else `runs`); a tie goes to the file.
   - Sight Run state: presets union (same JSON = same preset), best per range = the longer streak and the faster time, paced memo per range = the one with the later clean day, `last` from the file.
   - progress per piece: the record played last (`last`) wins, with the most plays, the best result by accuracy, the furthest Memorise stage and both sets of clean days.
   - simplify level, weekly snapshot, settings: the file's, as before.
   - Before an import runs, the whole current record is written as an export to `backup:last` (the last one only). Clear deletes it with the rest. There is no button to restore it: by hand, `importAll(await get('backup:last'))` merges it back, which does not undo a merge.
2. **Imported songs are in the export** (`songs`, bytes as base64) and come back on import; a song already here is kept as it is (the id is the file's hash). `navigator.storage.persist()` is asked once at boot (`main.ts`). Firefox may show a permission prompt for it.
3. **Read-modify-write saves queue.** `edit(key, empty, f)` reads, changes and writes in the existing `serial` queue: `markPlan`, `logHistory`, `addPractice`, `logTouch`, `addTake`, `setPick`, `addFile`, `removeSong`. `saveRuns`, `saveTech` and `saveScales` take an updater instead of a whole object, because their callers read, changed and saved across awaits (`drill.ts`, `read.ts`, `results.ts`). The whole-object saves (`saveDrill`, `saveTheory`, `saveQuiz`, `saveCoach`, `setSimplify`, `putSnap`) queue too, for ordering. The queue's turn holds `navigator.locks.request('piano-store')` where the browser has Web Locks, so two tabs take turns too.
   - Not fixed: the drill, theory, quiz and coach stats live in memory on their page and are saved whole, so two tabs practising at once still end with the last tab's copy. Fix: make those pages save per card through an updater too.
   - Export and import moved to `src/backup.ts`, loaded on use: the merge code put boot JS over the `bundle.test.ts` budget (243 321 against 241 200). `src/backup` is now on the list of modules that must stay out of boot.
4. **Stale heat.** `Progress.bars` holds the bar count the heat was kept for. `getProgress(id, bars)` returns no heat when the count differs, `commit(id, heat, bars, ...)` starts the heat again and trims it to the bars there are. `worstBars` (moved to `src/util.ts`, it now needs the bar count) never looks past the last bar, and `fixBars` clamps. Older records have no `bars`: they are trimmed, not wiped.
14. Importing the same file again keeps its track choice (the stored record is merged under the new one). `removeSong` deletes `simp:` too. Sharing an imported `.mxl` names it `.mxl` with type `application/vnd.recordare.musicxml` (plain MusicXML: `.musicxml`, `application/vnd.recordare.musicxml+xml`). The share fix has no automated test (`library.ts` is UI only).

## Service worker and deploy (`src/sw.ts`, `scripts/deploy.sh`)
5. A navigation answered with a non-ok status (Cloudflare 502 or 530 when quartz is down) is served the cached shell, this version's first. `scripts/offline.mjs` checks it: it answers `/` with 502 through `context.route`, which reaches the worker's own fetch in Chrome. Verified that check fails on the old worker.
6. `/corpus/catalog.json` is network-only: `src/catalog.ts` already keeps its offline copy in IndexedDB. Activate deletes the copy an older worker kept. `offline.mjs` now expects the catalogue fetch to fail offline.
7. Activate keeps the previous shell cache as well as this one (`stale()`, tested), so a tab still running the last build gets its lazy chunks. `deploy.sh` copies the previous `dist/assets` files younger than seven days into the new dist before unpacking (hashed names never change meaning, and the age limit stops them piling up forever). The snippet was run against local directories; the deploy itself was not run.
16. `r.update()` after `register()` in `main.ts` is gone. `?v=commit` is a new script URL each deploy, and registering a new URL starts the update at once; browsers also recheck the script on every navigation without the HTTP cache. The extra call was one more request per load.

## Parsers
8. **No empty last bar.** `quantize.ts` made bars while `tick <= endTick`, so a last note ending on a barline got one more bar, empty. Now it makes bars until it reaches every onset (a performed one up to `EARLY` before a barline belongs to the next bar) and every note that rings more than `TIE` (0.2 quarters, the threshold `notate` already used to write a tie) past a barline. Plain `<` broke the idempotence test: a performance's onsets snap a few ticks late, which pushed the last note's end over the barline on the second pass.
   - Bundled pieces that lose one bar (14 of 38, all MIDI): mutopia-1613, 202, 203, 2032, 2080, 354, 37, 463, 468, 471, 647, 67, 75, 79. Two more (1612, 504) still end with a bar holding no onset: their last note rings 2 quarters past the barline, a real tied tail.
   - **The published catalogue's `bars` and `sec` for MIDI pieces now differ from what the app computes.** Published 30 Oct as `28340171cad9bcbc` (`scripts/library/delta.mjs`: live plus what re-analysing at 3655165 and at 47cd8ec moves): 393 pieces, bars and sec 359, gradeWhy 303, notes 30 (the MusicXML fixes), grade 11, and `length` on mutopia-1938-2 and -62 (now under 10 s). Eight pieces stay as published, one bar long: mutopia-1009, 1010, 1477, 1483, 1484, 1614, 314 and 497, whose re-unfolded file is no longer the published bytes (the unfold lays its barlines on the app's bars), so the run lost their pickup.
9. A MusicXML file (or the score inside an `.mxl`) that starts with a UTF-16 byte order mark is decoded as UTF-16 LE or BE.
10. `&#228;` and `&#xE4;` are decoded in text and attributes.
11. `<attributes>` is read in document order inside the measure; a `<divisions>` change mid-measure rescales what has been counted so far.
12. **Ties.** The audit asked for "the held note must end where the stop starts". Run over the 12 119 corpus scores, that rule split 6 759 ties in 1 690 scores: most of them (gaps of a quarter to two quarters) are LilyPond's held arpeggios, where each note is tied to the chord it builds and must not be struck again. So the rule is: a tie-stop joins the held note of its pitch when it starts after that note began and at most `TIE_REACH` (4 quarters) after it ended, and the joined note lasts to the end of the note it is tied to (before, a held arpeggio note came out short by the gap). `<tied>` counts when a note has no `<tie>`. Against the old parser, 236 of 12 119 corpus scores now have a different note count (218 more notes: stray stops bars after a tie-start that never closed; 18 fewer); no score changes bar count or length. The one fixture that tied across a gap (`musicxml.test.ts`, the two-staff song) was a malformed tie and is now a dotted half tied to a quarter.
13. Simplify drops grace notes only, at every level above Full. Before, it also dropped every note under 80 ms, which on the bundled pieces removed fast written melody notes (mutopia-2146: 18 written 32nds at the top of the right hand; mutopia-1888: 14 staccatissimo top notes). Auto levels of all bundled pieces are unchanged; the melody levels of 2146, 1888 and 998 gain those notes.

## Security
15. Song ids in `data-*` attributes in `ui.ts` are escaped (a catalogue id comes from the network; `library-view.ts` already escaped its own). `index.html` has a CSP meta tag: `default-src 'self'; script-src 'self' https://static.cloudflareinsights.com; style-src 'self' 'unsafe-inline'` (the pages write `style=""` in their HTML); `img-src 'self' data: blob:; font-src 'self' data:; connect-src 'self' https://pianoforte.mattkelly.io https://cloudflareinsights.com; media-src 'self' blob: data:; worker-src 'self' blob:; object-src 'none'; base-uri 'self'`. The live site loads only its own origin plus Cloudflare's beacon script (checked with headless Chrome).
   - Pixi refuses to start without `'unsafe-eval'`, so `highway.ts` imports `pixi.js/unsafe-eval` (its no-eval shader path): the lazy `highway` chunk grows 290 kB to 303 kB, boot JS is unchanged. Without that import the play screen fails under the CSP (verified).
   - Checked with headless Chrome, dev server and `vite preview`: Today, Read, Scales, Theory, Technique, Progress, Settings and a song opened and played, no CSP violation and no page error. The e2e runs below run in dev under the CSP and fail on any console error.
   - The iPad app was not run. Its page origin is `capacitor://localhost`, which `'self'` matches; the corpus host is in `connect-src`; Capacitor's bridge is injected natively and is not subject to the page's CSP. One device launch should confirm it (`device-checks.md`).
