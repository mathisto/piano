# Shell fixes: Escape, stale opens, the way back, focus across redraws, the start card's column, the iPad app's shell

Sixteen defects from the 2026-10-30 audit (most confirmed in headless Chrome), on branch `feature/shellfix`. Nothing here was run on the iPad.

## Web app
1. **Escape in the Aids popover left the piece.** The popover now `preventDefault()`s its Escape and the global key handler (`src/app/input.ts`) skips any event already handled (`defaultPrevented`), so any later popover gets the same for free.
2. **A slow piece open took over after you moved on.** A navigation ticket in `state.ts` (`navAt`, `navigated()`), bumped by `showSection` and by every piece opened. `openSong(base, mode, paced, ticket)` bails before `view('play')`, after the stage loads and after the progress read when the ticket is stale, and returns `false`; `openLibrary` and stored files take the ticket before their fetch, so a slow download cannot take the screen either. `showSection` with no piece open ends whatever a feature set up for the abandoned open (a drill, Sight Run, read-through, memorise, calibration: `endFeatures()`, shared with `leave()` and the stage-load failure, which so far forgot calibration's delay). The drill callers return on `false`. This also ends e2e bug 6 (Escape right after Notes shown, then the reopen put you back).
3. **Two Songs renders in flight showed the open library twice.** `mountLibrary` removes its own section before it mounts: the last render wins.
4. **Redraws dropped keyboard and VoiceOver focus.** `keepFocus(root, render)` (`src/ui.ts`) records the focused control by id, else a radio by name and value (`focusKey`, `src/util.ts`, unit-tested), redraws, and puts focus back on the same control in the new markup. Used at the start card's single redraw in `onPhase` (Perform | Learn, You play, Notes shown, the memorise stage; the old hand-written refocus for You play is gone), the drawer, the Read tabs and the Sight Run form. Notes shown is arrow-navigable again: each arrow re-opens the piece and focus lands on the new choice.
5. **Leaving always went to Songs.** `openSong` keeps the page it was first opened from (a reopen keeps it), `leave()` returns there; a reading drill still goes to Read (its button says All stages). The results button (`#toLib`, also on the read-through and memorise cards) names that page.
6. **Escape mid-run left at once.** The first Escape pauses a run (count-in, playing, or Learn's waiting), the next one leaves.
7. **The PF button kept saying "leave this piece".** `leave()` resets it to "Piano Forte: Today".
8. **Leaving right after the last note threw in `results.ts`.** `onDone` works on the piece it started with: the commit, history, touch and scale records are still saved, only the card is skipped when you have gone.
9. **The start card was clipped on short stages and covered by the banner at 590x820.** The banner and the card share one flex column over the stage (`.stagecol`): the card centres between the banner and the keys, then drops onto the keys, then scrolls (`overflow: auto`, so it takes pointer events now). The old `top: 38%` plus translate and its per-height `top`/`bottom` overrides (style.css, accomp.css) are gone. At a split-view stage (340 px or less, 700 px wide or less) with the banner, a card with You play or Notes shown drops its title; the top bar has it.
10. **Duplicate top-level selectors in style.css.** Nine pairs merged into the first rule; `.bar > *` stays twice with a comment (its transition must follow `.btn`). Computed styles of every element on every page, the start card and the drawer were identical before and after at 820x1180, 1180x820 and 590x820. The audit's "16" counted rules across files and inside media queries; ten were true top-level duplicates. A test (`src/css.test.ts`) keeps one rule per selector. The orphaned doc comment in `state.ts` was the `sheets()` comment sitting above `chunkFailed`: moved back to `sheets()`.

Found on the way and fixed: Space on a switch (a checkbox) or anywhere in the drawer also started or paused the run behind it; now it only flips the switch. The drawer's grid rows shrank when the drawer overflowed the window, so a wrapped Data row overlapped the next; rows are `max-content` and the drawer scrolls.

## iPad app
11. `ios/App/App/PrivacyInfo.xcprivacy` in the target's resources: `NSPrivacyAccessedAPICategorySystemBootTime` with `35F9.1` (`mach_absolute_time` in `PianoNative.swift`), `NSPrivacyTracking` false, no tracking domains, no collected data. Capacitor and Cordova ship their own manifests (no required-reason APIs declared), and `strings` on both binaries finds no UserDefaults or file-timestamp calls, so `CA92.1` and `C617.1` do not apply. `ITSAppUsesNonExemptEncryption` false. (Moving the clock to `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)`, as `docs/research/ios-native.md` suggests for the timestamp fix, would make the manifest entry unnecessary; not done here.)
12. **Bluetooth pairing.** `CoreMidiPlugin.pairBluetooth` presents CoreAudioKit's `CABTMIDICentralViewController` in a navigation controller as a form sheet (centred on the iPad), with a Done button. On iOS 27 it applies Apple DTS's workaround for the 27.0 and 27.0.1 crash in `loadView` (a grouped `UITableView`, then `viewDidLoad()`; without that call it never scans; https://developer.apple.com/forums/thread/850584). CoreAudioKit is linked; `NSBluetoothAlwaysUsageDescription` is "Piano Forte connects to Bluetooth MIDI keyboards." A "Connect a Bluetooth keyboard" button (`data-pair`, one document listener) shows in the no-keyboard banner, the drawer's Keyboard row and Set up, and the MIDI chip pairs when no keyboard is connected; all only in the app. A paired keyboard is an ordinary CoreMIDI source, so the existing refresh lists it; since iOS 16 it reconnects by itself.
13. SceneDelegate is the one source of the window: `UIMainStoryboardFile`, the scene's `UISceneStoryboardFile` and `Main.storyboard` are gone (the storyboard's `CAPBridgeViewController` was a second root that SceneDelegate replaced). The empty template methods in AppDelegate went with them.
14. `TARGETED_DEVICE_FAMILY = 2` (iPad only) until there is an iPhone layout.
15. **Screen awake only during a run.** AppDelegate no longer sets `isIdleTimerDisabled` for good; `CoreMidiPlugin.setAwake({ on })` is called on each game phase change, on for count-in, playing and Learn's waiting (a learner reading a bar is still in the run), off otherwise.
16. **Build number.** A "Build number" run-script phase sets the built app's `CFBundleVersion` to `git rev-list --count HEAD` (359 at the time of writing); outside a git checkout it stays `CURRENT_PROJECT_VERSION` (1). It runs after Info.plist is processed and before signing (checked: `codesign -v` passes). `capacitor.config.ts` names `PianoNative.swift`.

`src/native-midi.ts` no longer imports `@capacitor/core` at boot: it tests for the app the way core's `isNativePlatform()` does (`webkit.messageHandlers.bridge`) and imports core only inside the app. Boot JS on the web is 234,563 bytes (241,454 with this branch's other changes and core still in boot, over the 241,200 budget); BUDGET lowered to 235,000 and the ratchet keeps `@capacitor/core` out of boot.
